# Испытания на целевой плате

Использовать второй независимый передатчик/приёмник с известными настройками.
В тестовый payload включать идентификатор радио, sequence number и контрольную
сумму данных, чтобы видеть потери до попадания в программную RX-очередь.
Для анализа CS/IRQ/BUSY полезен логический анализатор. На испытательном ядре
включить lockdep и KASAN, если позволяют ресурсы платы.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Один SX1262, обычные GPIO | Успешный SET_CONFIG, RX и TX с совпадающим payload |
| E22 через TCA9554 | Корректные CS/reset/BUSY/RXEN/TXEN и отсутствие одновременных CS |
| Восемь радио на одной SPI | Восемь устройств; независимые PHY-конфигурации; один TX в эфире |
| Две группы TX из разных процессов | Группы последовательны; фреймы внутри группы не перемежаются |
| Два IRQ во время высокого общего DIO_INT | Оба события обслужены, даже без второго фронта |
| RX по 1, 254 и 255 байт, два подряд | Нет искусственного reset/SetRx между корректными кадрами |
| Поток 10000 пар 255-байтовых фреймов | Подсчёт sequence gaps, измерение максимальной задержки IRQ до чтения RAM |
| Переполнение RX-очереди | Растёт rx_dropped; TX-результаты сохраняются |
| Не читать 32 TX-результата | Следующая заявка возвращает EAGAIN с O_NONBLOCK; чтение освобождает место |
| Частичное завершение группы и ошибка TX | frames_sent отражает подтверждённые TX_DONE; остаток не отправляется |
| CRC/header error | Пакет не попадает в read; последующий корректный принимается |
| Ложная преамбула без HEADER_VALID | Возврат в RX по короткому таймауту преамбулы, без ожидания полного пакета |
| HEADER_VALID без DONE/error | Возврат в RX по отдельному таймауту payload с учётом LDRO |
| Повторные PREAMBLE/HEADER IRQ без завершения | Дедлайн текущей стадии не продлевается |
| RX_DONE появился к истечению дедлайна, но IRQ потерян | Опрос регистра обрабатывает пакет и снимает дедлайн до решения о recovery |
| Implicit RX без HEADER_VALID | Достаточный таймаут на полный кадр фиксированной длины |
| Обрыв IRQ при работающем SPI | Растёт polled_irqs; по тишине выполняются soft/hard recovery |
| Нет трафика более двух интервалов watchdog | Soft recovery, затем hard recovery; RX после этого работает |
| Длинная преамбула/SF12, узкая BW | Watchdog не обрывает допустимый кадр раньше расчётного дедлайна |
| BUSY одного модуля удерживается высоким | Ограниченный timeout, reset виновника; очередь остальных продолжает работу |
| close во время группы | Текущая передача остановлена reset; остаток группы отменён |
| unbind во время read/TX, затем bind | Нет use-after-free/hang; ожидающие fd разбужены; новое устройство работает |
| Неверные ioctl/длины/зарезервированные поля | Ошибка без частичного TX и без повреждения состояния |
| E22 и внешний PA на нескольких мощностях/частотах | Измеренные мощность и ток соответствуют DT-профилю; при необходимости таблица исправлена |

Потери при недопустимо коротком межкадровом интервале должны быть измерены
отдельно: программная очередь не устраняет ограничение аппаратного буфера
SX1262 и задержки доступа через GPIO-расширитель.

## Доступ к эфиру перед группой TX

- Подать заявку во время приёма длинного кадра: RX должен дойти до приложения
  до начала TX; ожидание не удерживает SPI/io и не выключает RX watchdog.
- Начать RX во время случайного backoff: TX откладывается до завершения RX,
  затем выполняется новый backoff. Проверить IRQ и резервный опрос IRQ.
- Поддерживать занятость дольше `2 × airtime(255) + 1000 ms`: получить TX-событие
  `-EBUSY`, `frames_sent=0`; убедиться, что отложенного выхода в эфир нет.
- При двухфреймовой группе проверить отсутствие backoff/SetRx между фреймами.
- Во время ожидания выполнить close/unbind: нет передачи старой заявки после
  повторного open/bind, нет зависания общей очереди.
- При ложной преамбуле проверить, что watchdog снимает RX-состояние и TX может
  начаться после backoff. При отказе радио очередь остальных продолжает работу.

## Проверка TCXO и преамбулы, 2026-11-18

RNS-Gate → Lilygo T-Deck (ratspeak, USB RNode в raw/promiscuous режиме),
расстояние около 1 m. rnsd остановлен. Частота 868672500 Hz, BW 62500 Hz,
SF8, CR 4/7, мощность E22 8 dBm, sync 0x1424, explicit header, CRC включён,
LDRO выключен, TCXO 1.8 V. Две серии размеров 16/64/128/184/220/254/255 bytes,
между завершёнными одиночными TX-заявками пауза 500 ms. Каждая серия начинает
с SET_CONFIG; T-Deck между сериями не перенастраивался.

| TCXO startup | Преамбула | Принято / отправлено |
| --- | --- | --- |
| 5 ms | 25 | 5 / 14 |
| 21.5 ms | 25 | 7 / 14 |
| 21.5 ms | 49 | 14 / 14 |
| 21.5 ms | 25, повтор после 49 | 5 / 14 |

Все принятые кадры первых трёх серий побайтно совпали с отправленными.
Во всех сериях драйвер подтвердил все TX без ошибок. Увеличение задержки
TCXO само по себе потери не устранило; зависимость от длины преамбулы
воспроизведена обратным переключением. Это не устанавливает физическую
причину потерь и не гарантирует отсутствие потерь на других устройствах.
E22 startup оставлен 21.5 ms для соответствия прежнему плагину; напряжение
не повышалось. Изменение startup не следует считать исправлением потерь.

Дополнительная проверка установленного плагина с преамбулой 49: отправлены
пакеты 1/254/255/500 bytes (6 физических кадров). В полном синхронном
USB-захвате получены только 4 кадра: 2/255/2/247 bytes; их payload совпал.
Потеряны одиночный кадр пакета 254 bytes и первый фрагмент пакета 500 bytes.
Все четыре вызова send вернули успех. Поэтому преамбула 49 сама по себе
также не является полным исправлением: нужны дальнейшие проверки условий
перехода RX/TX и приёмника при последовательных передачах.

## Установленная причина потерь на T-Deck

В RNode RX был настроен на преамбулу 18 символов, E22 передавал 25.
Согласно Semtech SX1261/2 datasheet 6.1.3, RX должен быть настроен на
максимальную преамбулу передатчиков. При одинаковых 18 символах получены
14/14 кадров, побайтно совпадающих с переданными. В ratspeak-handheld RX
отделён от TX: приём настроен на max(65, TX preamble), длина TX не менялась.
После этого исходные 25 символов E22 дали 14/14 кадров без потерь.
Три серии через установленный плагин (1/254/255/500 bytes) дали 12/12
полностью собранных RNode-пакетов, включая оба фрагмента, с совпадением данных.
Это заменяет прежнюю рабочую гипотезу о задержке TCXO. Пробы XOSC fallback
и отключения промежуточного TX IRQ polling улучшения не дали и отменены.

## Раздельные преамбулы, ABI 2

Установлены модуль ABI 2 и плагин 0.3.0. Конфиг платы обновлён:
`rx_preamble_symbols: 65`, `tx_preamble_symbols: 25`.
Обратный пакет T-Deck → E22: 16 bytes, точное совпадение.
Затем три серии через плагин по 1/254/255/500 bytes: 12/12 собранных пакетов,
все байты совпали, без потерь фрагментов. rnsd в тесте не запускался.
Проверки на хосте покрывают независимость RX/TX airtime и таймаутов,
implicit RX, диапазоны обеих преамбул и отклонение конфигурации ABI 1.
